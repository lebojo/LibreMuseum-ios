# LibreMuseum — iOS

Visitor app for a museum, fed entirely by
[LibreMuseum-pocketbase](https://github.com/lebojo/LibreMuseum-pocketbase).

The app is an **empty shell**: it ships no text, no image, no colour. The museum name, its logo,
its palette, its exhibitions and its audio guides all come from the server. Direct consequence:
**the museum changes its content without going through the App Store**. The developers' work is
limited to installing the server once, then publishing the app once.

## What the visitor gets

| Screen | Content |
| --- | --- |
| Home | The museum, its logo and its colours, then the current exhibitions. |
| Exhibition | Its description, its schedule, and the list of its artworks. |
| Artwork | Photographs, facts, full text, and the audio guide in the chosen language. |
| Map | The floor plans, one pin per placed artwork, floor by floor. |
| Search | The whole artwork index, by title, artist or wall code. |
| Info | Address, phone, email, website, and the practical pages the museum publishes. |
| Settings | Language, content version, cache size. |

Content loads **screen by screen**. The local copy is displayed instantly, the network refreshes
it behind: the visitor never waits in front of an empty screen, and inside a museum — where the
network is the exception — the app keeps working on its latest copy.

An artwork with no audio guide published offers a **read-aloud** button instead, which speaks the
description with the best voice installed on the device, under an "Autogenerated" badge.

Exhibitions that **require a ticket** hide their artwork list behind a QR code, scanned or typed;
the description stays readable without one. How long the unlock lasts is the museum's decision,
through `museum.ticket_validity_hours`.

Interface labels are localised — English source, complete French translation. The *content*
language is the visitor's own choice, among the ones the museum publishes.

## Running it locally

You need **Xcode 26 or newer**: the project uses the `objectVersion = 110` format, which earlier
versions cannot open. Minimum target iOS 18.6, iPhone and iPad.

The app is useless without a server. Start one:

```bash
git clone https://github.com/lebojo/LibreMuseum-pocketbase
cd LibreMuseum-pocketbase && ./scripts/dev.sh --seed   # :8090, bilingual demo museum
```

Then build and run:

```bash
xcodebuild -project LibreMuseum.xcodeproj -scheme LibreMuseum \
  -destination 'generic/platform=iOS Simulator' build
```

To run it rather than just build it, open the project in Xcode, or name one of your own
simulators — `xcrun simctl list devices available` lists them. In the simulator there is nothing
to sign, and the default server address already points at the local one.

## Pointing the app somewhere else

The server address is **not** written in Swift. `Configurations/Server.xcconfig` holds it,
injects it into `Info.plist`, and `APIConfiguration` reads it at launch. The default,
`http://127.0.0.1:8090`, is what the simulator needs.

A physical device does not reach your machine through `127.0.0.1`, and a real museum runs
somewhere else entirely. Both cases go through the same non-versioned file:

```bash
cp Configurations/Server.local.example.xcconfig Configurations/Server.local.xcconfig
```

Fill in the address. Git ignores that file, so your server never shows up in a diff — and nobody
has to remember to revert it before committing. Signing works the same way, through
`Configurations/Signing.local.xcconfig`; `CONTRIBUTING.md` covers it.

## Repository layout

```
Core/           API, Repository, Sync, Media, Localization, Theme, Tickets — no views
Models/Data/    DTO (mirror of the server JSON) + Entities (@Model SwiftData)
Models/UI/      flat models suffixed `UI` + Mapping/
Views/          one folder per view that has subviews; Components/ for the reusable ones
Extensions/     Color and Font styles
Configurations/ xcconfig files and the Info.plist they feed — signing and server live here
```

`AGENTS.md` documents what the code deliberately does not: the PocketBase API traps this project
has already paid for, the invalidation invariants, and the compiler constraints that come with
`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. Read it before touching `Core/` or a DTO.

## Good to know

**The padlock discourages, it does not protect.** `unlock_code` travels in the exhibition
response and is compared on the device, and the artworks stay readable through the public REST
API — as they must, for an app with no visitor account. It keeps an honest visitor out of a
paying exhibition; it is not access control. Do not put behind it anything that would harm the
museum if read.

**No visitor account, no analytics, no tracking.** The app reads a public API anonymously. The
only thing it stores about the visitor is their language choice and the tickets they scanned, on
their own device.

**The media cache survives a content update.** Text is re-downloaded when the server's content
fingerprint moves; images and audio are not, because their path already contains the record id
and the file name. A visitor who paid for storage does not pay again for the same bytes.

**The server is pre-1.0.** [PocketBase](https://pocketbase.io) makes no backwards-compatibility
guarantee, so verify an API assumption with `curl` before writing code against it. The traps
already found are in `AGENTS.md`.
